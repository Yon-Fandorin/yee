# Yee Agent 검증 결과

이 문서는 현재 사람이 읽을 결과 요약이다. 수치와 판정의 기준은
[`comparison.json`](comparison.json)과
[`evidence-index.json`](evidence-index.json)이며, 서로 다르면 JSON을 따른다.
과거 후보의 필요한 비용과 실패 정보는 비교 JSON 안에 보존한다.

## 현재 판정

고정 범위는 원래 12개 시나리오를 cold·지속 세션과 fixture seed 11·29로
조합한 48개다. 사람의 승인·선택·인증 대기는 비교 시간에서 0초로 통제하고
횟수와 실패 비용은 유지했다.

| 표본 | 통과 | 대기 제외 시간 | 실제 총 토큰 | 모델 호출 | MCP 호출 / 오류 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 현재 Yee | 46/48 | 2,386.330초 | 5,201,651 | 238 | 164 / 4 |
| 재사용한 Aside | 36/48 | 3,708.277초 | 11,930,211 | 463 | 375 / 19 |

전체 실패 비용을 포함한 합계에서 Yee는 Aside보다 시간이 35.65%, 토큰이
56.40% 적었다. 두 제품의 통과 수가 다르므로 이 합계는 현재 표본의 기술적
비교이며 동일 성공 집합의 통계적 우위 선언은 아니다. 현재 Yee는 직전 완료
Yee보다 시간은 1.32% 줄었지만 토큰은 0.78% 늘었다. 따라서 정확성을 유지한
전체 시간·토큰 동시 개선 목표는 아직 달성하지 못했다.

실패한 두 건은 모두 S09 seed29다.

- cold: 사용자가 반품 방법을 물었지만 관찰된 자료에 절차가 없다는 설명까지
  답변에 포함하지 못했다.
- 지속 세션: 배송비 3,000원의 출처를 문의가 아닌 정책 문서로 잘못 연결했다.

두 경우 모두 Native 입력과 실제 저장 본문은 같았고 발송은 0회였다. 저장
손실이나 실행기 실패가 아니라 답변 완전성·출처 귀속 실패다. 통과한 동일 조건
쌍에서도 persistent seed29 S05는 Yee가 약 29.70초 느렸고, cold seed11 S05는
Yee가 649토큰 더 사용했다. 이 예외를 합계 우위에서 숨기지 않는다.

## 유지한 제품 변경

외부 변경이나 문서 교체 직후 첫 관찰이 잘못된 delta로 전달되던 baseline 문제를
수정했다. 소비자가 기준을 모르는 경우와 문서가 바뀐 경우에만 full snapshot을
요청하고, 이미 기준이 있는 동일 문서의 delta는 유지한다. 이전 구현에서 재현된
13개 실패가 해소됐고, 오프라인 영향 검사 206개와 실제 SDK 구조 gate가 통과했다.
이 보정은 유지하지만 현재 46/48 결과나 토큰 증가를 성공으로 바꾸어 해석하지
않는다.

승인 UI는 단일 텍스트 alert에서 구조화된 Native 카드로 바뀌었다. Agent 식별,
요청 제목, origin, 작업 상세, 안전 안내와 명확한 동작 버튼을 분리했고 긴 내용은
300 DIP 안에서 스크롤한다. 승인 기본 선택은 계속 취소이며 질문은 별도 입력란과
비밀번호·인증 코드 경고를 사용한다. 장식 아이콘의 접근성 이름, 투명 합성 표면의
서브픽셀 텍스트, 일반 Widget의 모달 수명 문제를 Chromium Views 규칙에 맞게
고쳤고, 부모 Yee 창의 화면 bounds를 기준으로 중앙 배치한다.

승인 UI 소스는 격리 Yee UI 빌드와 통합 앱 빌드를 통과했다. 브리지 계약 검사
45개가 통과했고, 실제 앱에서 1,440×900 부모 창 안에 512×430 모달이 중앙 배치된
가시 상태와 무크래시 렌더링을 확인했다. 현재 Computer Use 캡처는 별도 Native
자식 모달을 주 창 이미지에서 누락하므로 픽셀 단위 캡처는 남은 시각 검증이다.

## 남길 교훈

- 최신 판정은 하나의 비교 JSON과 증거 색인에서 파생한다. 날짜별 Markdown의
  숫자를 다시 현재 결론으로 복사하지 않는다.
- Aside는 모델·프롬프트·fixture·seed·viewport·승인 정책·세션 조건이 같을 때
  재사용한다. Yee만 바뀌었다는 이유로 전체 Aside 시험을 반복하지 않는다.
- 실행기 문제와 제품 문제를 분리한다. 정답 기준이나 안전 검사를 실행기 성공률에
  맞춰 약화하지 않는다.
- 실패·중단·재시도 비용을 성공 표본 밖으로 버리지 않는다. 관찰 시간 초과를
  프로세스 종료로 해석하지 않고 정확한 실행 핸들을 확인한다.
- 시나리오 ID·seed·정답 값 분기보다 capability, schema, 완료 receipt와 기준 상태를
  개선한다. 단일 표본의 추가 탐색을 없애기 위한 벤치마크 전용 힌트는 넣지 않는다.
- Native 모달은 `DialogWidget`, 불투명 루트, 합성 표면용 텍스트 렌더링과 올바른
  접근성 역할을 함께 확인한다. 주 창 캡처에 모달이 없다는 사실만으로 미표시라고
  판정하지 않는다.
