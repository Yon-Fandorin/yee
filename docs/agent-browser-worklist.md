# Yee Agent 다음 작업

현재 판정, 수치와 실패 원인은 [검증 결과](agent-browser-validation/results.md)를
따른다. 이 문서에는 아직 해결되지 않은 작업만 둔다.

## 다음 우선순위

1. S09 seed29 두 실패의 공통 원인을 고친다. 관찰 자료에 답이 없을 때 그 한계를
   명시하고, 문의 값과 정책 값의 출처를 분리하는 범용 규칙이어야 한다. 시나리오
   ID·seed·정답 값 분기는 허용하지 않는다.
2. 실제 입력 증가와 반복 문맥 전송을 분석해 직전 Yee 대비 확인된 토큰 증가를 줄인다.
   cache·noncache·output을 분리하고, 모델 호출 수가 같은 표본의 API 변동은 제품
   개선 효과로 간주하지 않는다.
3. 승인 카드의 light/dark, 긴 요청, 질문 입력, 키보드 취소와 접근성 화면을 실제
   Native 자식 창까지 캡처하는 도구로 확인한다. 현재 빌드·무크래시·중앙 배치는
   확인됐으며 주 창 전용 캡처만 부족하다.

## 실행 원칙

- 변경 영향 사례를 먼저 재현하고 구조 변경을 묶은 뒤에만 고정 48개를 반복한다.
- Aside 조건이 그대로면 기존 baseline을 재사용한다. 조건이 달라진 자료만 보완한다.
- 실패 비용, 원본 응답과 Native receipt를 보존하며 실행기 문제로 제품 판정을
  바꾸지 않는다.
- 필수 gate가 통과하고 시간·토큰 목표가 확인되면 추가 후보 탐색을 멈춘다.
