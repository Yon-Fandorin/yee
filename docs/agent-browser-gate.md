# Yee Agent 검증 기준

현재 기능 검증, 특정 표본의 성능 비교와 일반적인 우위 주장을 구분한다. 수치와 판정은 [기계 판독 비교](agent-browser-validation/comparison.json)와 [증거 색인](agent-browser-validation/evidence-index.json)을 기준으로 하고, [검증 결과](agent-browser-validation/results.md)는 그 사람이 읽을 요약이다. 다음 후보는 [다음 작업](agent-browser-worklist.md)을 따른다.

## 고정된 필수 검증

원래 [12개 시나리오](agent-browser-scenario-suite.md)를 cold 단독 작업/실제 지속 세션, seed 11/29에서 각각 검증한다. 총 48개이며 일부 시나리오 통과로 전체를 대신하지 않는다. 현재 고정본의 통과 여부는 최종 결과를 따른다. 추가 안전 gate·Luna/Kimi 직접 모델의 원래 판정·Native 실제 앱 검증의 범위와 재사용 근거는 최종 기록에 명시한다.

- 사용자 요청의 정답, 필수 정보, 정확한 저장·최종 상태, 권한과 부작용을 확인한다. S03 최종 제출0회, S09 발송0회, S12 비밀번호/OTP 모델 전달0회 등 원래 조건을 유지한다.
- 잘린 viewport를 전체 문서로 간주하지 않는다. 긴 문서의 본문·예외·각주·출처는 모델이 실제 수신한 무손실 내용과 최종 답변을 대조한다. 원본 archive가 있다는 사실만으로 모델 수신을 입증하지 않는다.
- 문서/ref freshness, 대상·비밀값 검사, 승인·취소, settlement, 결과 미확정과 부분 실행을 확인한다. 실행기 오류를 고치려고 제품 동작이나 정답 기준을 바꾸지 않는다.
- 실패·재시도·중단과 원본 요청/응답·Native receipt를 보존한다. 수정 전/후 다른 후보의 비용은 분리하여 함께 공개한다.

## 비교 조건과 Aside 재사용

현재 비교 대상은 Yee/Aside이며 브라우저끼리는 같은 모델을 사용한다. 현재 48개 표본은 선언된 Grok 4.6/high, timeout240초, 요청 재시도0, 원래 12-turn 판정 조건, viewport1440×900/dpr1이다. provider 내부 재시도와 실제 hard cap을 관측하지 못한 범위는 미확인으로 둔다. 모델 설정이나 원래 판정을 변경하지 않는다.

교정 Aside baseline은 실제 모델·프롬프트/프로필·fixture hash·seed·viewport·승인 정책·cold/지속 조건과 원본 비용이 맞으면 재사용한다. Yee만 변경한 경우 Aside 전체 재시험을 요구하지 않는다. 공통 조건의 변경 영향이나 누락이 있으면 해당 자료만 보완하고, 다른 조건의 과거 결과를 현재 표본으로 섞지 않는다. 작고 결과에 중요하지 않은 조건 차이를 사용자가 명시적으로 수용한 경우에는 운영 비교로 표시할 수 있지만, 정확히 일치한 표본처럼 표현하지 않고 차이의 크기·영향과 엄격히 일치한 보조 표본을 함께 기록한다. 재사용 근거와 원본 SHA는 [증거 색인](agent-browser-validation/evidence-index.json)에 기록한다.

Browser Use와 Codex Browser는 신규 비교·연결 복구 범위에서 제외한다. Grok/Kimi/Luna의 Yee 직접 사용 호환성 검증은 비교 대상 선택과 별개다. 다른 모델의 결과를 Aside 대비 속도 우위로 합산하지 않는다.

## 비용 기록과 판정

원시 전체 시간은 준비·연결·발견·실행·최종 응답·독립 검증·정리와 실패 비용을 포함한다. 비교 시간은 기록된 사용자 승인/선택/인증 대기를 0초로 통제한다. 자동 ACP 처리와 실행기 시간은 임의로 제거하지 않는다. 승인 종류별 횟수, 모델/MCP 호출, 오류·재시도와 미계측 항목을 별도로 공개한다.

실제 input/output/cache/reasoning 사용량을 기록한다. cache는 input의 일부, reasoning은 output의 일부이며 이중 합산하지 않는다. 누락된 사용량·승인 횟수는 unknown이지 0이 아니다. bytes·로컬 tokenizer 추정치를 실제 provider 토큰의 대체 우위 지표로 사용하지 않는다.

정확성과 안전성을 유지하며 **전체 시간과 실제 총 토큰 모두 줄어드는 것**이 개선 목표다. 직전 완료 Yee 대비 변경 효과와 Aside 대비 표본 차이를 따로 보고한다. 현재 표본의 통과 수와 직전 Yee/Aside 대비 실제 차이는 최종 결과에서 각각 판단한다. 실패한 Aside 사례의 비용을 제외하여 우위를 선언하지 않는다.

현재 두 seed의 고정 표본은 통계적·모든 사이트·모든 시나리오의 우위를 증명하지 않는다. 과거 설계안의 최소3-seed·양방향 반복 권고도 충족했다고 주장하지 않는다. 이는 잔여 한계이며, 완료된 필수 48개 뒤에 자동으로 추가 GUI 시험을 시작하는 지시가 아니다.

## 변경에 따른 확인 범위

MCP만 변경하면 관련 오프라인 계약 검사와 실제 모델 영향 사례를 먼저 확인한다. Native/UI를 변경하면 `AGENTS.md`의 빌드·실제 앱·layout tier gate를 따른다. 별도 Native 자식 모달은 주 창 캡처만으로 판정하지 않고 위젯 상태·bounds와 자식 창 화면·입력 경로를 확인한다. Native가 동일하면 소스와 앱 hash가 결속된 기존 검증을 재사용하고 대형 Chromium 빌드를 반복하지 않는다.

구조 개선을 고정한 뒤 필수 전체 gate를 수행한다. 결과를 통과시키기 위한 후속 후보가 필요하면 실제 실패와 비용을 남긴다. 필수 gate 완료 뒤에는 추가 탐색을 멈추고 최종 표와 잔여 한계를 보고한다. 오래된 HOLD, 종료된 PID나 계획서를 현재 실행 명령으로 해석하지 않는다.
