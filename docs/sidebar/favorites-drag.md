# Favorites drag

Favorites와 Tab 목록 사이, 그리고 독 안에서의 드래그 결정이다. 목표는 Tab
목록을 끌 때와 같은 **타일이 마우스를 따라가고, 다른 칸이 자리를 비우는**
느낌이다.

## 보이는 것

드래그 중인 원본 칸은 숨긴다. 따라가는 미리보기는 Tab Sidebar 위에 둔다.
ScrollView에 잘리지 않게 하기 위해서다.

Favorite이 하나도 없으면 평소에는 독의 자리도 보이지 않는다. 실제 Tab
드래그가 시작된 동안에만 76 DIP 점선 드롭존을 열고, 드래그가 끝나거나
취소되면 다시 접는다. 열 때는 레이아웃 높이를 160ms 동안 펼치고 표면은 30ms
늦게 페이드 인한다. 취소할 때는 높이와 표면을 120ms 동안 함께 접는다. Group
드래그에는 이 드롭존을 열지 않는다. 작은 높이에서도 안내가 먼저 읽히도록
제목과 설명은 기존보다 한 단계 크게 쓴다. 안내색은 고정하지 않고 현재 테마의
frame·label 색과 Yee shell tint, 드롭존 fill을 합성해 계산한다. 제목은 최소
7:1, 설명은 최소 4.5:1 대비를 유지하며 별과 점선은 계산된 제목색에서 파생한다.
모션 감소 설정에서는 즉시 전환한다.

마지막 Favorite을 집으면 원래 독 대신 Favorite이 0개일 때와 같은 76 DIP 점선
드롭존을 바로 보여 준다. 포인터가 Tab 영역으로 넘어가도 드롭존과 76 DIP
레이아웃 공간을 드래그가 끝날 때까지 유지한다. 따라서 다시 Favorite으로
돌아갈 수 있고, 경계를 오갈 때 Tab 목록이 움직이지 않는다. Tab 영역에 드롭이
완료되면 드롭존의 레이아웃 공간을 즉시 제거한다. 점선 표면만 레이아웃과
분리된 잔상으로 90ms 동안 페이드 아웃해, Tab 목록이 늦게 당겨지는 느낌 없이
커밋 순간을 부드럽게 마무리한다.

| 포인터 위치 | 미리보기 |
| --- | --- |
| Favorites 독 위 | 아이콘 칸 (활성 칸과 같은 dimmed 카드). 가로로도 포인터를 따른다 |
| Tab 목록 위 | 제목 행. 가로는 Sidebar에 맞추고 세로만 포인터를 따른다 |

같은 영역 안에서는 클릭한 칸의 크기와, 그 칸 안에서 잡은 픽셀 오프셋을
유지한다. 드래그가 시작되는 순간 타일이 커서 아래로 튀지 않는다. 독과 목록
사이를 넘으면 모양과 크기가 바뀐다.

## 독 안에서 재배치

- 미리보기 타일의 **중심이 올라간 칸**이 목적지다. 칸 앞에 끼워 넣기만 하면
  마지막 칸에 겹쳐도 가운데로 간다.
- 세 개가 한 줄일 때 첫 칸을 세 번째 칸에 겹치면 맨 뒤가 된다.
- 이웃 칸은 빈자리를 만들며 밀린다. 빈자리는 그리지 않은 구멍이다. 원본
  타일이 그 구멍에 다시 그려지면 깜빡인다.
- 밀리는 애니메이션은 420ms, 가속 후 감속이다. 중간에서 목적지가 바뀌면
  현재 위치에서 이어 간다.

모델 갱신은 독 안에서 바로 일어난다. 컨테이너를 바꿔 가며 retarget하지
않는다. 빈 독이나 다른 컨테이너로 타깃을 바꾸면 크래시가 난다.

## 영역 사이

독과 Tab 목록 / Group 사이를 넘을 때는 컨테이너를 바꾸지 않는다. 목적지에
시각적 빈자리만 열고, pin/unpin은 드롭이 끝날 때 커밋한다.

- Tab → Favorites: 용량이 남으면 pin. 독에 착지 칸이 열린다. 목록에서는
  원본 행이 접힌다. Favorite이 이미 하나 이상이면 기존 타일 옆의 빈 칸이
  실제 삽입 위치를 보여 준다. 목적지 독의 **추가된 뒤 칸 수**로 타일 폭과
  hit 경계를 함께 계산하므로 Favorite이 하나일 때도 기존 타일의 왼쪽과
  오른쪽을 각각 선택할 수 있다. 12개가 이미 있으면 독 위에 있어도 pin하지
  않는다. 이 거절 상태는 일반 Tab 목록 드래그와 구분해 Chromium의 기본 재배치
  경로도 차단한다. 따라서 Favorite 미리보기나 빈 칸을 보여 주지 않고, 드롭해도
  원래 Tab 순서가 바뀌지 않는다.
- Favorites → Tab: unpin. 목록과 Group이 빈자리를 연다. 다른 Favorite이
  남아 있으면 독의 원본 칸이 접히고, 마지막 Favorite이면 0개 상태의 드롭존을
  드래그가 끝날 때까지 유지한다. 드롭 시 보인 빈자리의 인덱스를 실제 Tab
  순서에 커밋한다.
  독 바로 아래 경계는 첫 Tab 앞의 빈자리다. 첫 Tab의 아래쪽 빈자리에 놓으면
  첫 번째가 아니라 그 Tab 다음에 배치된다.

영역을 넘어 도착한 요소는 처음부터 최종 크기와 공간을 차지한다. 도착 요소의
레이어만 최종 위치보다 왼쪽 10 DIP에서 시작해 240ms 동안 빠르게 감속하며
오른쪽으로 이동하고, 같은 시간 동안 투명도 0에서 1로 올라간다. 이 모션은
Tab → Favorites와 Favorites → Tab에 동일하게 적용한다. 같은 영역 안의
재배치와 도착 요소 주위의 이동은 기존 컨테이너 애니메이션을 그대로 쓴다.

마지막 Favorite을 Tab에 놓는 성공 경로에서는 드롭존을 모델의 unpin 커밋이
끝날 때까지 유지한다. 드롭 종료 도중 한 칸 독을 다시 보여 주지 않으며, 커밋이
끝나면 높이 애니메이션 없이 드롭존과 공간을 한 번에 제거한다. 이때 표면만
레이아웃에 참여하지 않는 잔상으로 복제해 90ms 동안 페이드 아웃한다. Chromium의
삭제 애니메이션을 위해 남아 있는 원본 View는 Favorite 존재 여부에 포함하지
않아, 드롭존 뒤에 빈 한 칸 공간이 다시 나타나지 않는다.

빈 Favorites 드롭존의 hit magnet은 드롭존 아래로 늘리지 않는다. 그래서
Favorite이 0개여도 첫 Tab의 위쪽 절반은 첫 번째 Tab 삽입 위치로 쓸 수 있다.

Group은 정리 UI일 뿐, 드롭 대상 그룹 위에 있으면 그 그룹 안에 빈자리를 연다.
이때 포인터를 따르는 제목 행도 실제 Group Tab과 같은 leading inset과 폭을
사용한다. Favorite, 비그룹 Tab, 다른 Group Tab 중 어디에서 시작해도 이 들여쓰기
신호는 동일하다. Group 경계를 드나들 때 목적지 판정은 즉시 바뀌되 미리보기의
leading inset과 폭은 120ms fast-out-slow-in 모션으로 이어져 계층 변화가 튀지
않는다. Tab 영역과 Favorites 독 사이를 드나들 때도 현재 미리보기의 가로 위치와
폭에서 행 또는 타일의 최종 geometry로 같은 리듬을 사용해 전환한다.
Group 안의 삽입 위치는 이전 프레임에 열어 둔 빈자리를 제외한 원래 Tab 행 좌표로
매번 다시 계산한다. 따라서 여러 Tab이 있는 Group에서도 최초 진입 위치에 고정되지
않고 포인터가 가리키는 모든 중간 위치와 맨 앞·맨 끝으로 계속 이동할 수 있다.
포인터와 정렬된 미리보기 행의 중심이 각 Group Tab 중심보다 위면 그 Tab 앞,
아래면 그 Tab 뒤를 선택한다. 그래서 첫 Tab의 위쪽 절반과 마지막 Tab의 아래쪽
절반도 다른 중간 슬롯과 같은 크기의 실제 드롭 구간을 가진다.
이때 슬롯 판정은 원시 커서 좌표가 아니라 화면에 그리는 Tab 행 미리보기와 동일한
bounds를 사용한다. Favorite 타일에서 잡은 지점은 Tab 행 높이에 맞게 비례 변환되므로
아이콘의 위·가운데·아래 어디서 드래그를 시작해도 같은 시각적 위치는 같은 슬롯을
가리킨다.
Group 헤더는 Group 내부 첫 슬롯이 아니라 바깥 Tab 목록에서 그 Group 바로 앞에
놓는 경계다. 미리보기의 중심이 헤더 아래 실제 Group Tab 본문에 들어온 뒤부터
Group 내부 맨 앞·중간·맨 끝 슬롯으로 판정한다.
Favorite이 Group의 중첩 컨테이너에 처음 진입하는 순간에도 native 재배치를 먼저
실행하지 않는다. Group은 unpinned 영역의 목적지로 분류하고, 드롭 완료 전까지
Favorite 모델 순서와 pin 상태를 유지한다.
최상위 Tab 목록의 삽입 위치 역시 이전 프레임에 열린 빈자리를 제외한 compact
좌표로 계산한다. Group 내부와 같은 원칙을 사용하므로 바깥 첫·중간·끝 슬롯도
이전 목적지에 달라붙지 않는다.
포인터의 세로 위치는 보간하지 않으며, 동작 줄이기 설정에서는 Group과
Favorites를 포함한 모든 가로 geometry 전환을 즉시 적용한다. leading inset은
논리 좌표로 계산해 RTL에서도 실제 Group Tab과 같은 시각적 오른쪽 가장자리를
기준으로 움직인다. 미리보기는 LayoutManager가 아닌 직접 bounds로 배치하므로,
RTL의 x 좌표와 아이콘·제목 배치도 명시적으로 반전한다.
마지막 Tab 아래의 빈 Sidebar도 Tab 목록의 끝으로 취급한다. ScrollView가
콘텐츠 높이로만 접혀 빈 사이드바에서 드롭이 끊기지 않는다. 이 끝 빈자리에
놓으면 현재 원본 위치와 무관하게 마지막 순서에 커밋하며 한 칸 앞으로 당기지
않는다.

## 오른쪽 끝

독의 마지막 칸 오른쪽, 그리고 독 높이에서 위로 한 Tab 행만큼 여유를 둔 띠로
콘텐츠 쪽으로 나가면 **새 창이 아니라 마지막 Favorite 순서**다. 아래쪽으로는
Tab 드래그와 Favorite 드래그 모두 magnet을 늘리지 않아, 독 바로 아래를 첫 Tab
앞 경계로 판정한다. 그 띠에서 벗어나 페이지 쪽으로 내려가면 목록 드래그/분리로
넘어갈 수 있다.

창 밖으로 완전히 나가면 Chromium처럼 탭을 떼어 새 창을 만들 수 있다.

## 탭이 하나뿐인 창

탭이 하나뿐이어도 드래그 시작 직후에는 창 이동보다 Sidebar 정리를 먼저
처리한다. 포인터가 같은 창의 Sidebar 안에 있는 동안에는 일반 Tab과 동일하게
Favorites 등록, Favorites 해제와 목록 배치를 미리 보여 주고 커밋한다. 단일
Tab이 그룹에 속해 있더라도 Tab 자체를 집은 경우에는 이 규칙을 적용하지만,
Group 헤더를 집은 경우에는 적용하지 않는다.

포인터가 Sidebar를 벗어나면 지연 시간 없이 Chromium의 기존 창 이동 경로로
넘긴다. 빈 바탕화면에서는 새 복제 창을 만들지 않고 현재 단일 Tab 창 자체를
이동한다. 다른 Yee 창의 Sidebar로 들어가면 그 창으로 Tab을 옮기며, 그 창의
Favorites 독에 놓으면 목적지 창의 Favorite으로 등록한다. 성공적으로 다른
창에 옮겼을 때만 원본 단일 Tab 창을 닫고, 취소하면 원래 창과 pin 상태를
복구한다.

이 예외는 `TabStripModel`의 Tab 수와 실제 드래그 Tab 수가 모두 1일 때만
적용한다. 여러 Tab을 모두 선택한 드래그와 가로 Tab Strip의 Chromium 동작은
바꾸지 않는다.

## Native 회귀 체크리스트

Group 하나와 비그룹 Tab 하나가 있고 각각 Tab을 한 개씩 가진 최소 구성에서
Favorite을 Tab 목록으로 드래그해 확인한다. 미리보기의 빈자리와 드롭 뒤 실제
모델 순서는 항상 같아야 한다.

아래 동작의 모델 결과는 `test-sidebar.sh interactive`가 자동 확인한다: 일반
Tab·Group Tab·Favorite 출발점, Tab → Favorites의 좌·우 슬롯과 용량 거절,
Favorites → 최상위 Tab의 처음·끝, 펼친 Group의 처음·중간 retarget·끝과 헤더
경계, 접힌 Group 뒤, 취소 복원, 단일 Tab 창 안의 pin/unpin. 0개·마지막 1개·
여러 개 Favorite 드롭존의 실제 View 수명주기와 Group 들여쓰기 정렬도 자동으로
확인한다. 전체 매핑은 [test-coverage.md](./test-coverage.md)에 둔다. 체크리스트에는
애니메이션의 연결감과 시각적 계층처럼 사람이 실제 화면에서 판단해야 하는 부분을
유지한다.

- [ ] 비그룹 Tab이 세 개일 때 Favorite을 첫 Tab 앞, 각 Tab 사이의 두 중간
      빈자리, 마지막 Tab 뒤에 각각 놓을 수 있고 네 위치 모두 실제 순서에
      그대로 커밋된다.
- [ ] Favorite이 하나 있을 때 일반 Tab을 독으로 드래그하면 기존 Favorite의
      왼쪽과 오른쪽 슬롯을 각각 선택할 수 있고, 미리보기·빈자리·커밋 순서가
      일치한다.
- [ ] 펼친 Group 앞, Group과 비그룹 Tab 사이, 비그룹 Tab 뒤의 세 최상위
      빈자리에 각각 배치할 수 있다.
- [ ] 접힌 Group에서도 Group과 다음 비그룹 Tab 사이를 Group 밖 빈자리로
      판정하고 배치할 수 있다.
- [ ] 펼친 Group의 첫 Tab 앞과 뒤에 배치할 수 있고, 드롭 뒤 Favorite이 해당
      Group의 멤버가 된다.
- [ ] Group 내부 목적지가 바뀌면 기존 Group Tab이 빈자리를 열며 밀리고,
      중간에 목적지를 바꿔도 현재 위치에서 애니메이션이 이어진다.
- [ ] Group 내부 빈자리와 Group 밖 경계 빈자리는 들여쓰기·정렬 또는 Group
      범위의 반응으로 서로 구분되며, 같은 목적지처럼 보이지 않는다.
- [ ] Group의 펼침 상태와 무관하게 포인터가 가리킨 계층(그룹 내부/최상위)을
      드롭 종료까지 유지하고, native drag target 변경이 이를 덮어쓰지 않는다.
- [ ] Favorite·비그룹 Tab·다른 Group Tab에서 각각 시작해 펼친 Group으로
      드래그하면 미리보기 행이 Group Tab과 같은 leading inset으로 정렬되고,
      Group 밖으로 나오면 일반 Tab 정렬로 복귀한다. 경계를 빠르게 왕복해도
      x/폭 모션이 현재 위치에서 이어지며 포인터의 세로 추적과 실제 드롭 대상은
      지연되지 않는다.
- [ ] Tab 영역과 Favorites 독 경계를 양방향으로 빠르게 왕복해도 미리보기의
      가로 위치·폭이 현재 frame에서 이어지고, 세로 포인터 추적과 실제 pin/unpin
      대상 판정은 지연되지 않는다.
- [ ] RTL에서 Group 진입·이탈 미리보기의 들여쓰기 방향과 폭이 실제 Group Tab의
      시각적 leading edge(오른쪽)와 일치한다.

## 하지 않는 것

- 독 안에서 착지 칸에 원본 타일을 그려 미리보기와 겹치기
- 포인터가 칸 중심을 넘을 때만 자리 바꾸기. 타일이 올라간 칸이 기준이다.
- 드래그 중 pinned/unpinned 컨테이너를 서로 갈아끼우기
- 오른쪽 끝으로 살짝 나갔을 때 새 창 띄우기
