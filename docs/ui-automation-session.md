# macOS UI 자동화 운영

이 문서는 재현 가능한 실제 앱 검증 절차와 장애 판정만 기록한다. 만료된
`caffeinate` PID, 일회용 bridge 경로, 중간 인증 시도와 세션별 진행 보고는 제품
근거가 아니므로 보관하지 않는다.

## 실행 절차

1. `swift tools/dev/check-ui-session.swift`로 세션을 확인한다. exit 20은 잠금,
   exit 21은 검사 불가다. exit 0은 잠금이 보고되지 않았다는 뜻이며 화면 캡처
   권한이나 창 탐색 성공까지 보장하지 않는다.
2. `zsh tools/dev/run-agent-prototype.sh`를 사용한다. 실행기는 기존 Yee를 정상
   종료한 뒤 새 빌드와 일회용 프로필·bridge를 연다.
3. 실제 fixture 탭, accessibility tree와 화면을 확인한 뒤 Native 승인과 필요한
   작업을 수행한다. 기존 프로세스에 새 빌드를 덧씌워 검증하지 않는다.
4. CLI 결과, Native receipt와 화면 결과를 각각 확인한다. 한 채널의 성공을 다른
   채널의 증거로 대신하지 않는다.
5. 종료 시 정확한 Yee 실행 파일을 정상 종료하고 해당 실행에서 만든 프로필만
   제거한다. 다른 세션이나 다른 브라우저의 프로필은 건드리지 않는다.

## 장애 판정

- 화면이 잠겨 있으면 사용자가 직접 잠금을 해제한다. 비밀번호를 자동화에
  전달하지 않는다.
- `cgWindowNotFound`는 잠금, 화면 녹화 권한, 앱·창 매칭을 각각 확인한다. 실행
  프로세스가 있다는 사실만으로 UI가 검증 가능하다고 판단하지 않는다.
- 관찰 대기 시간이 끝났다는 사실만으로 작업이 종료됐다고 판단하지 않는다.
  정확한 세션·프로세스 핸들과 결과 파일을 확인한다.
- CLI 결과와 화면이 다르면 visual PASS로 처리하지 않는다. 문서 교체, 오래된
  accessibility snapshot, 잘못 선택한 창과 renderer 갱신을 분리해 확인한다.
- Native 자식 모달은 주 창과 별도 캡처 surface일 수 있다. 주 창 스크린샷에서
  보이지 않더라도 위젯 가시성·bounds, 자식 창 캡처와 실제 입력 경로를 확인한다.

## 운영 원칙

- 실제 사용자 조작이 끼어든 실행은 제품 실패 표본으로 재사용하지 않는다. 원본은
  남기고 통제된 조건에서 다시 실행한다.
- 자동 잠금 방지는 작업 환경 설정이며 제품 저장소의 현재 상태가 아니다. 시스템
  설정 변경 기록, 임시 device code와 인증 정보는 문서에 남기지 않는다.

기능별 판정과 성능 수치는 [Agent 검증 결과](agent-browser-validation/results.md)를
따른다.
